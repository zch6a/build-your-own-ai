# Polish log

Each round goes through the whole project — every chapter's claims checked against a run, the code
read top to bottom, tests, first-run experience, docs (English and Chinese), CI, and a record here —
then a local commit.

## Development

- [x] **Scope.** Eight chapters, each a module in `byoai/`, a walkthrough and a demo in `chapters/NN-*/`,
  and tests: tokenizer, autograd, GPT, inference, vector database, RAG, agent, MCP. Constraints chosen
  up front: numpy is the only dependency; nothing to download (no model weights, no datasets); no API
  key — agent and RAG chapters will run on the chapter-3 model or a deterministic stand-in, with an
  optional adapter for any OpenAI-compatible endpoint (DeepSeek included) for those who have one.
- [x] **Training text** (`byoai/corpus.py`): a seeded grammar of short stories — generated, so there is
  nothing to license and every machine trains on the same text; small and regular enough for a tiny
  transformer to learn on a CPU.
- [x] **Chapter 1 — byte-level BPE tokenizer** (`byoai/tokenizer.py`): training with word counts and
  incremental pair updates (264 merges on 400 KB in 0.02 s), encoding by merge rank with a chunk
  cache, opt-in special tokens (a document cannot inject `<|endoftext|>`), save/load. 31 tests,
  including round trips of text the tokenizer never saw (other scripts, emoji, control characters).
  The demo shows something worth knowing: on this corpus training stops after 264 merges because every
  word is already one token — `vocab_size` is an upper bound — and says so instead of hiding it.
- [x] **Chapter 2 — autograd** (`byoai/autograd.py`): a `Tensor` that records its inputs and a backward closure; iterative topological sort (a 5,000-op chain does not hit the recursion limit); broadcasting undone as a sum; batched `@`, reshape, transpose, integer-array indexing with `np.add.at` (repeated token ids get both gradients), `masked_fill`, `softmax`, `log_softmax`, fused `cross_entropy` (stable at logits of ±1000), `layer_norm` built from primitives, GELU, `concatenate`; `no_grad`; AdamW (decay on matrices only); `gradcheck`. 35 tests — every operation checked against finite differences. One bug found by its own test: float32 tensors got float64 gradients (reductions return a numpy *scalar*, which the constructor upcast) — it matters for chapter 3's speed. Demo: hand-derived vs. autograd gradients, a finite-difference check, a 2-64-64-3 network learning three spirals to 100% in about a second, drawn as an ASCII map.
- [x] **Chapter 3 — GPT** (`byoai/gpt.py`, `byoai/zoo.py`): GPT-2's architecture (token + position embeddings, pre-norm blocks, multi-head causal attention, GELU MLP, residuals, weight tying, GPT-2 initialization), AdamW with warmup + cosine and gradient clipping; the shared story model is trained once and cached by a key of everything that determines it. 392k parameters train in 102 s on a CPU to held-out loss 0.62 (untrained 6.30); stories are new (checked sentence by sentence against the training text). Tests: loss at init ≈ ln V (a first version used targets = inputs, and an untrained tied model leans toward its input token — the test was wrong, not the model), causality, a full gradient check of every parameter (tiny gradients ~1e-7 now compared absolutely: finite-difference noise), memorizing a sequence, weight tying, save/load.
  - **Speed, profiled twice**: 290 ms/step at first. A constant like `1/sqrt(D)` wrapped as a `Tensor` became a 0-d *float64 array*, which NumPy 2 promotes float32 to (a bare Python number it would not) — most of the pass ran in double precision; constants now take the tensor's dtype. `(B,T,C) @ (C,3C)` became one 2-D BLAS product with the weight gradient summed directly. Plus no float powers in GELU/sqrt, no gradient copies (clipping now makes new arrays). 1.47 s → 0.32 s/step for the largest size tried.
  - **The phase change, measured**: keeping the first sentence's animal in the second — 22% after 500 steps, 9% after 1,000 (chance: 10%), then **53% after 1,500 and 65% after 2,000**, with the held-out loss dropping from 0.609 to 0.550 (copying was predicted to be worth ~0.14 nats/token). A thousand steps on a plateau, then the copying circuit forms suddenly — the induction-head phase change, reproduced on a laptop. `chapters/03-gpt/longer.py` reproduces it (using chapter 4's KV cache for the evaluation; the first version of the experiment generated without it and took 10 minutes per measurement). **Re-run before writing it up**, and the timing moved: the second run jumped at step 750 (19% → 70%) and kept the animal 100% from 1,500 on. The chapter now shows both runs side by side and says what is stable (the suddenness) and what is not (when) — the first draft's "for a thousand steps nothing happens" would have been false for half of the readers who ran it.
- [x] **Chapter 4 — inference** (`byoai/generate.py`): a numpy engine on the trained weights with a KV cache (prefill, then decode one position at a time; rebuilt from the recent half when the 64-position window fills), sampling (temperature, top-k, top-p), stop tokens, streaming. The cached logits equal a full forward pass at every step (1e-5); greedy matches chapter 3. Demo, measured: 10.7× faster with the cache (122 → 1,317 tokens/s); greedy writes the same story every time (2% distinct); temperature 0.5–1.0 is fluent (86–88% of sentences valid in the grammar), 1.5 breaks (68%), 2.5 is nonsense (0%); top-k / top-p bring temperature 1.5 back to 85%.
- [x] **Chapter 5 — vector database** (`byoai/vectordb.py`): `FlatIndex` (one matrix product, `argpartition`), `HNSWIndex` (layers with geometric level sampling, two-heap beam search, the paper's neighbour-selection heuristic with fill-up, pruning on overflow, soft deletes that still route, save/load), `clustered_vectors`, `recall_at_k`; `Engine.embed`. 11 tests. Measured: on 8,000 vectors HNSW looks at 6% of them for recall@10 0.938 (ef=64) and 0.993 at ef=256; work grows 1.5× while the collection grows 8×. The heuristic is worth 20 points of recall over "keep the nearest M" (0.897 vs 0.698).
  - **Build speed**: 38 s for 3,000 vectors at first — the heuristic did a numpy call per candidate pair. All pairwise distances in one product, then plain floats: 10 s.
  - **The test data was wrong, not the index**: recall on random Gaussian vectors was 0.87. Noise in 32 dimensions has no structure to navigate (all points nearly equidistant) and is nothing like embeddings, so the tests use clustered data on a curved 8-dimensional surface and keep the strict thresholds (>0.9 at ef=64, >0.97 at ef=128).
  - **What an embedding holds**: searching 1,196 corpus sentences with the model's mean hidden state finds the same *template* (cosine 1.000 for one-word swaps; "the owl and the key" → "It was cold and the cat was tired"); a TF-IDF bag of words finds the owl and the key. Centring the vectors did not change it. The chapter explains why (next-token training rewards knowing the grammar position, not the topic), what real embedding models add (contrastive training), and the demo is honest that numpy flat search beats a Python HNSW on time at this size.
- [x] **Chapter 6 — RAG** (`byoai/rag.py`, `byoai/llm.py`, `knowledge_base()`): 60 articles about invented towns (each fact in one of three phrasings, most sentences without the name) and 360 questions. Chunking at sentence boundaries with overlap and title headers; BM25 with an inverted index (checked against the formula by hand); LSA (TF-IDF → SVD → chapter 5's `FlatIndex`); reciprocal rank fusion; hit@1/hit@k/MRR; `build_prompt`; `SentenceReader`; `RAG`. 19 RAG tests + 8 client tests against a fake HTTP server. Demo runs in 2 s.
  - **Measured lessons**: the title header is worth 0.17 hit@5 at 40-word chunks (0.93 vs 0.76) and doubles it at 10 words; LSA's better hit@5 (0.98) turned out to be "returns the whole article" (all top results from the right article 72% vs 56%), not understanding — hit@1 is equal; LSA at 16 dimensions cannot keep 60 names apart (0.19).
  - **The reader, three iterations**: (1) idf from chunks made "mayor" nearly worthless with whole articles (in every one) — idf now over sentences; (2) "How many…" matched "remark on *how* quiet" — question words ignored; (3) 6–9% confidently wrong answers came from neighbour articles that *mention* the town ("The nearest town is Nustorford") — a passage must now be *about* the name (its title). Result: 69% correct, 31% "I don't know", **0% wrong**, and the 69% equals the ceiling with the right article handed over (the share of phrasings that share a word with the question), so retrieval at k=4 loses nothing.
  - **The model client is off by default**: nothing is sent unless `BYOAI_LLM_BASE_URL` is set — a `DEEPSEEK_API_KEY` alone does not switch it on (tested). Never run against a real endpoint here (it would spend the user's tokens without consent).
- [x] **Chapter 7 — agent** (`byoai/agent.py`, `byoai/planner.py`): the loop (wire-format assistant/tool messages, several calls per turn), `@tool` schemas from type hints and docstrings, `validate` (missing/unknown/wrong type, `True` is not an integer), errors fed back as tool results, `max_steps`, a repeated-call guard, result truncation, `safe_eval` (AST walk, exponent cap; 7 attacks tested) and `sandboxed_reader` (resolve-then-check, symlink escape tested). `TownPlanner`, a stateless offline stand-in model for four task kinds over the chapter-6 towns, `Noisy` (cut-off JSON, misspelled tool, wrong argument name), `agent_tasks`. 31 tests; demo in 1 s.
  - **Found by measuring**: the planner first failed 16% of "age" tasks and trying the other wording did not help — BM25's length penalty ranks a short chunk that only *names* the town above the long chunk with "It was founded in 1375". The fix is the agent's real advantage over a fixed pipeline: notice the answer is missing and search differently (the town alone, 10 results). 84% → 100%; the demo shows all three stages. (Also a regex that missed "About 19,300" with a capital A — caught because "total" tasks sat at 44%.)
  - **Error feedback, measured**: with 10/30/50% of tool calls spoiled, feeding errors back keeps 100/99/93% success (the rest is the 8-turn limit) vs 80/54/27% for the naive loop; costs 0.3 turns per task at 10%.
- [x] **Chapter 8 — MCP** (`byoai/mcp.py`): `MCPServer` (initialize with version negotiation, notifications without replies, ping, tools/list, tools/call; protocol errors −32700/−32600/−32601/−32602 vs tool errors as `isError` results; schema validation server-side; stdout reserved for the protocol, UTF-8/`\n` forced on Windows), `MCPClient` (subprocess, reader thread + queue, timeouts, id matching, non-JSON lines skipped, polite shutdown by closing stdin), remote tools as chapter-7 `Tool`s, `python -m byoai.mcp [--notes DIR]`. 14 tests, including a real subprocess server and an agent over MCP. Demo in 2 s.
  - **Measured**: 199/199 tasks over MCP with answers identical to in-process tools; the process boundary costs 0.10 ms per call; server start ≈ 0.5 s.
  - **Found by testing**: a client whose `initialize` timed out left the hung server running (the test's child slept 30 s) — the client now kills it on a failed start, and the test asserts it returns in < 10 s.
  - Not verified against a real MCP client (that would mean changing the user's Claude Code config); compliance is checked against the 2025-06-18 message shapes.
- [x] **All 8 chapters done** — 166 tests. Next: five polishing rounds.

## Round 3

- **Checked against external sources** (a fresh agent compared chapters 1–8 with the MCP specification, OpenAI and DeepSeek API docs, the HNSW, BM25/RRF, GPT-2 and induction-head papers, and tiktoken's patterns; 14 findings):
  - *The DeepSeek setup no longer worked*: `deepseek-chat` is being retired (DeepSeek's changelog), and its thinking models — on by default — return `reasoning_content`, which with tools **must be sent back** on later turns (400 otherwise). The client now keeps it and the agent echoes it only when present (OpenAI requests unchanged); docs use `deepseek-flash` and say that providers rename models. Tests for both paths.
  - *MCP had moved on*: 2025-11-25 is now accepted, and chapter 8 gains a "Versions" section: what 2026-07-28 changes (no handshake, `server/discover`, `_meta`, no server requests on stdio) and why this server still works with new clients (they fall back to `initialize` on −32601). Invalid arguments: 2025-06-18 said protocol error, 2025-11-25 says `isError` result — this server follows the newer rule, now stated.
  - *Client spec gaps*: shutdown now goes stdin-close → SIGTERM (TerminateProcess) → SIGKILL; a timed-out request is cancelled with `notifications/cancelled`; `tools/list` pages are followed via `nextCursor`. Tests with the tricky server (two pages; cancellation message checked).
  - *HNSW deviated from the paper*: new nodes got 2·M links on layer 0; Algorithm 1 gives M, and 2·M is only the cap for backlinks.   - *Induction heads described wrongly*: it is a previous-token head plus an induction head that both finds and copies (Olsson et al. 2022), not "one finds, one copies"; and they do not form in one-layer models — which exercise 5 now rests on.

  - Checked and correct: MCP handshake fields, version negotiation, stdio rules, `claude mcp add` syntax, OpenAI tool-calling shapes (`content: null` beside `tool_calls` is valid), RRF k=60 (Cormack et al. 2009), contextual retrieval, HNSW mL = 1/ln M and the heuristic, GPT-2 facts.
